# Local Game Pilot 0.1.0

Windows のゲーム画面をローカル画像対応 LLM に送り、注入した目標・攻略知識に沿って操作を選ぶツールです。添付の「ゲーム攻略くん」の画面観測→操作→再観測という考え方を参考にした独立実装です。添付版の .NET、OCR、C++ ランチャー、外部ソースを本体に同梱していません。

**現時点の位置付け：実装・自動テスト済みの開発版です。全シーンからの実ゲーム攻略を実証した完成品ではありません。** Linux の開発環境には対象ゲーム・Windows デスクトップ・実際の画像対応 LLM がなく、その組合せを検証できていません。開発中の人間によるゲームテストは依頼していません。

## 機能

- Ollama と OpenAI 互換ローカル API（llama.cpp / LM Studio 等）に対応。
- スクリーンショット、攻略目標、攻略知識、直近12手の観測・操作履歴を毎回送信。
- タイトル、読み込み、会話、メニュー、プレイ中、敗北、勝利などをモデルが毎回判断。固定の開始シーンを前提にしません。
- 小目標、観測根拠、選択理由、信頼度、操作、完了・判断不能を表示。
- 知識ファイルの読み込みと編集、目標・設定の保存。
- 操作の JSON 検証、キー許可リスト、時間・手数上限、低信頼度で操作しない処理、F8 停止。
- 推論後の画面が大きく変わった場合は再観測。前面がゲーム以外になった場合は停止。
- 操作予定・実行記録を JSONL に保存。モデルの判断履歴はプロセス内の直近12手で、長期学習DBではありません。
- 本体は自前のソースのみ。依存部品の選択メニュー、モデルのストリームダウンロードを用意。

## Windows での導入

1. ZIP を書き込み可能な場所に展開し、`setup.bat` を開きます。
2. Python（3.12以上、3.13推奨）を公式ページから選択してインストール。Tcl/Tk、pip、Python Launcher を含めてください。複数バージョンがある場合は `py -3` が対象版を選ぶよう環境を設定します。
3. ローカルLLM実行環境を選びます。推奨は Ollama。既存の llama.cpp / LM Studio も利用できます。外部ランタイムのインストーラーは公式サイトから取得し、利用者が実行します。
4. `start.bat` で本体を開き、「環境・モデルの選択と取得」で Pillow を導入します。既存環境を分離する場合は次の手順を使います。

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m autoplayer
```

5. Ollama を起動し、モデルを選択してダウンロードします。画像対応モデルが必須です。目安は qwen2.5vl:3b 約3.2GB、7b 約6GB、32b 約21GB、gemma3:4b 約3.3GB。実際の容量はタグの更新で変わります。必要なRAM/VRAMはファイル容量より多く、CPU実行では低速になります。モデルごとの利用条件は情報リンクで確認してください。
6. API URL とモデル名を設定します。

| 実行環境 | API形式 | URL例 | 注意点 |
|---|---|---|---|
| Ollama | ollama | http://127.0.0.1:11434 | 選択したモデルを事前に取得 |
| llama.cpp | openai | http://127.0.0.1:8080 | 画像対応モデルと対応 mmproj を読み込んで起動 |
| LM Studio | openai | http://127.0.0.1:1234/v1 | 画像対応モデルを読み込み、ローカルサーバーを有効化 |

Ollama 以外のモデルは各実行環境のメニューから取得してください。本体には GGUF / mmproj を自動選定する機能はありません。接続先は localhost に限定し、画像はローカル API に送ります。ランタイム・モデル取得にはインターネット接続が必要です。

## 使用

- ゲームを起動し、ウィンドウモードにします。ゲーム起動自体は本ツールの対象外です。「起動画面」は起動済みゲームのタイトルやロゴを指します。
- 対象ウィンドウに固有のタイトル文字列を指定します。同じ文字列に複数のウィンドウが一致した場合は操作しません。
- 攻略目標と具体的な達成条件を入力します。`knowledge/torneko.md` を読み込んで攻略知識を追加できます。ボタンの意味はゲームのキー設定に合わせて記述してください。
- 「観察のみ」をオンにすると実際の画面を見て判断しますが、キーは送りません。自動操作する場合はオフにします。
- 「保存して開始」を押し、5秒以内にゲームを前面にします。開始時の画面をそのまま認識します。
- 停止は F8。別のウィンドウを前面にしてもキー送信を止めます。API要求はタイムアウトまで残る場合がありますが、停止後に返ってきた操作は実行しません。
- 再開すると、その時点の画面から再判断します。目標・知識は保持しますが、直近のモデル会話は新しい実行でリセットされます。

本版の操作は前面キー入力です。裏でゲームを動かしながら他アプリを操作する用途には対応していません。画像は画面上のクライアント領域なので、他ウィンドウによる遮蔽やキャプチャ保護の影響を受けます。管理者権限が異なるアプリやゲーム独自の入力方式ではキーが届かない場合があります。

## 記録と制限

`data/settings.json` に目標・知識・設定、`data/runs/*.jsonl` に判断と実行結果を保存します。画像はディスクに保存しません。目標達成・危険な確認の認識はモデルの判断であり、正確さは保証できません。ゲーム内容の危険な操作を機械的にすべて検出する仕組みではありません。

リアルタイムの高速操作やフレーム単位の反応は対象外です。推論中に画面が変化し続ける場合は停止します。ダンジョン地図の永続管理、アイテム知識の自動獲得、長期計画の検証器は未実装です。そのため「任意のシーンから確実に完全攻略」という要求の達成は未確認です。

## 自動検証と配布

```sh
python -m unittest discover -s tests -v
python tools/package.py
```

テストは実HTTPの模擬サーバーで両APIの画像・知識送信を検証し、制御側のシーン列・停止・不正操作拒否・記録失敗・画面変化などを検証します。模擬応答によるシーン列テストは、LLMの画像認識能力や実ゲーム攻略成功の証明ではありません。

配布 ZIP は `dist/LocalGamePilot-0.1.0-source.zip`。外部依存、モデル、履歴、キャッシュを除外します。Python がない環境でも `setup.bat` の外部ランタイム選択メニューは開けます。署名済みの単体 exe ではありません。
