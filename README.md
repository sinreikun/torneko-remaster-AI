# Local Game Pilot 0.5.0

**元ソース仕様のUI・検証機能にLLM攻略機能を統合した版です。実ゲームとの連携・攻略は未検証です。架空のデモゲームは使用しません。**

Windows のゲーム画面をローカル画像対応LLMへ送り、目標・攻略知識に沿って操作するツールです。

## 利用者の起動方法

**[LocalGamePilot.exe をダウンロード](https://github.com/sinreikun/torneko-remaster-AI/raw/refs/heads/main/release/LocalGamePilot.exe)して実行してください。** Python の手動導入やコマンド操作は不要です。

1. 初回のみ、exe を実行するとセットアップUIが開きます。準備済みなら次回から本体が直接開きます。EXE更新時も導入済みの部品と設定を再利用します。
2. Python の版、LLM実行環境、画像モデルを選択します。それぞれに用途・容量・ライセンスの説明があります。
3. 利用条件を確認し「自動セットアップして起動」を押します。
4. 必要な部品のダウンロード・検証・導入、Ollama の起動、モデル取得が自動で進み、準備完了後に本体が開きます。
5. ゲームをウィンドウモードで起動します。「目標・攻略知識・接続設定」で対象ウィンドウを選び、「ゲームに接続」→「攻略開始」を押します。最終目標と攻略知識は初期設定済みです。ゲームを前面にする必要はありません。背面の対象ウィンドウを直接取得・操作します（最小化はしないでください）。
6. 一時停止・再開、停止、F8 / Ctrl+Shift+F9 に対応します。「観察のみ」はキーを送りません。
7. 停止・エラー時に診断ZIPを自動生成します。「提出用ZIPをコピー」を押すと、ファイルを添付欄へ貼り付けられます。「最新ZIPを開く」から保存先も開けます。

本体exeは約130KBです。外部ランタイムやモデルを同梱せず、自前の起動処理・UI・アプリソースだけを埋め込んでいます。Windows 10/11 x64 の Windows PowerShell 5.1、.NET Framework、Universal CRT といった標準機能を使用します。独自の署名証明書は付与していません。

## 自動導入の選択肢

| 項目 | 選択肢 | 自動処理 |
|---|---|---|
| Python | 3.14 / 3.13 | 公式の最新安定版x64インストーラーを取得。Tcl/Tk・pipを含めユーザー用領域に導入 |
| 画面取得 | Pillow 12系 | Pythonへ自動導入・import検証 |
| LLM実行環境 | Ollama の自動導入 / 起動済みOllamaの再利用 | 公式ポータブル版を取得・展開・起動。既存環境ではランタイム取得を省略 |
| OCR（任意） | Windows内蔵 / PP-OCRv5 / 日本語PP-OCRv4 | セットアップで選択後に自動導入。元ソース実測のモデルサイズ・SHA-256を検査 |
| 画像モデル | qwen2.5vl:3b / 7b / 32b / gemma3:4b | Ollama APIでダウンロード。進捗表示・完了確認・画像対応能力の確認 |

知識を含むCPU推論には数分かかる場合があるため、推論の待機上限は初期値600秒です。「セットアップ」で1〜600秒に変更できます。

モデル容量の目安は順に約3.2GB / 6GB / 21GB / 3.3GBです。必要なRAM/VRAMは容量より大きく、実行速度はCPU・GPU・画像サイズに依存します。Ollama の公式Windowsアーカイブにも数百MB〜数GBの空き容量が必要です。初回セットアップにはインターネット接続が必要です。

Python は公式発行元署名、Ollama は公式 GitHub API の SHA-256 と照合してから利用します。APIの制限時は公式リリースページに掲載されたSHA-256を使用し、検証条件は維持します。検証できない配布物は実行しません。Python の最新情報は python.org の公式Windows配布一覧から読み取ります。

保存先は `%LOCALAPPDATA%\LocalGamePilot`。管理者権限やPATHの編集は要求せず、導入したランタイムを明示的に使用します。選択内容・導入済み部品・モデルは次回起動で再利用します。OSが組織管理によりPowerShellやダウンロードを制限している場合は、その制限を解除する処理は行いません。

- `python-3.14/` または `python-3.13/`: 実行環境
- `ollama/`: ローカルLLM実行環境
- `models/`: 自動導入したOllamaのモデル
- `app-0.5.0-<内容のハッシュ>/`: アプリ本体
- `data/settings.json`: 目標・知識・設定
- `data/runs/*.jsonl`: 判断・操作の記録
- `data/memory.sqlite`: 計画、経験、仮説、状態間の遷移
- `data/diagnostics.sqlite`: 互換性・分離試験専用（学習から分離）
- `data/recordings/<実行ID>/`: 実画面・時刻・画像ハッシュ・記録上限等の統計
- `data/sessions/`: 停止理由と実行サマリー
- `data/exports/`: 自動生成された提出用診断ZIP
- `data/ocr-tests/`: OCR比較結果（学習に使用しない）
- `downloads/`: 検証対象のダウンロードファイル

自動導入したOllamaは `127.0.0.1:11435` で待ち受けます。モデルを再利用できるよう本体終了後もサーバーは残ります。既存Ollamaの標準ポート11434とは分離します。画像はローカルAPIへ送ります。OCR用の一時画像は処理後に削除します。OCR文字と認識領域・画像のハッシュは診断記録に保存します。

## 初代・リマスターの攻略知識とOCR

公式サイト・Steam・初代の二次資料を調べ、25件の出典付き知識を同梱しました。初代の宝石箱・幸せの箱・追加攻略、ターン、満腹度、回復、所持品、帰還、罠、敵、店・倉庫などを含みます。リマスターのバランス調整や追加DLCは別の知識として扱います。[出典と照合の仕様](knowledge/SOURCES.md) / [構造とデータの流れ](ARCHITECTURE.md)

Windows標準OCR、または導入済みのPP-OCRv5 / 日本語PP-OCRv4から現在画面の文字・矩形・時刻・画像ハッシュを取得し、出典・対象版と照合してローカルLLMへ渡します。LLMが小目標・可視達成条件・理由・OCR根拠を自ら設定し、後の画面と矛盾した知識を保留・修正します。これらはSQLiteとJSONLに残り、次の判断と再起動後に利用されます。OCR利用不能時も理由を記録して画像認識を続けます。

OCRの用語一致やモデルの評価はゲーム仕様の実証とは扱いません。初代固有の数値をリマスターの確定値として使わず、全体目標と小目標の達成を分けて検証します。

## 攻略機能

- 毎回スクリーンショットから現在のシーンを判断し、固定の開始画面を仮定しません。
- 目標・攻略知識の関連部分・直近の履歴・SQLiteに保存した計画と経験をモデルへ渡します。
- 小目標、進捗、操作の結果を記録して再起動後も利用します。仮説は訂正可能であり、確定事実と区別します。
- 旧版の監査に基づく安定待ちと局所アニメ処理を取り入れています。
- 不正な応答・一時的なAPI障害は再観測して再試行し、停滞時には失敗した操作を渡して再計画します。
- 完了宣言は新しい画像を別のモデル呼び出しで検証します。
- 状況・小目標・観測根拠・理由・信頼度・操作を表示します。
- 許可キー、操作時間、手数の上限、不正JSONの拒否、低信頼度時の操作抑止があります。
- 推論中に画面が大きく変わった場合は操作せず再判断します。
- F8 または停止ボタンで停止します。ゲームが背面になっても攻略を継続します。API要求が終了する前に停止しても、戻ってきた操作は実行しません。
- 「観察のみ」はキー送信なし。初期状態は自動操作です。
- ウィンドウモードのゲームを対象にします。背面キャプチャ（PrintWindow）とウィンドウ宛てキー入力に対応するゲームが必要です。Raw Input 専用・背面で描画や入力を停止するゲームでは動作が制限されます。ゲーム本体の起動は利用者が行います。

本体はOpenAI互換ローカルAPIにも対応していますが、この版の起動UIが自動導入するLLM実行環境はOllamaです。llama.cpp / LM Studioの自動導入は実装していません。

## 元ソースに沿った統合UI・検証

上部に接続・開始・一時停止・停止・OCR・セットアップ・診断出力を配置。左にライブ画面と「観測→行動→結果」、右に元ソースと同じ13項目に対応する状態・目的・判断・仮説・修正・統計パネルを配置しています。折りたたみ状態は表示設定として保存します。LLMの小目標・可視達成条件・OCR根拠・知識改訂を同じ画面へ合流させました。詳しくは[仕様の対応表](INTEGRATION.md)を参照してください。

- 起動時診断：特定キーやメニューを使わず、WM_NULLのOS送信受付だけを確認。ゲーム側の反応・キー受理とは分けます。
- 分離監視：10分間のOS経路・無入力観測。入力分離を実証したとは表示しません。実探索の送信結果・画面反応の統計は専用DBへ保存します。
- 無入力を中立観測として扱い、入力前の自然変化と入力後の観測を分けて記録。無反応だけでは自動停止しません。
- LLMの説明文は日本語を指定。終了位置・サイズ・最大化状態を保存して復元します。
- OCRテスト：実画面の取り直し、画像ファイル、Windows / V5 / V4の比較、領域表示、JSON保存。未導入や失敗はそのまま表示し、結果を捏造しません。
- 実機記録：判断前と操作後の実画像を非同期で保存。1実行128MiBまでとし、欠落・上限到達も記録します。軽量ZIPは28MiB以下で、直近ログ・サマリー・少数の画面・health.txtを含みます。大きなDBを省略した場合は検査結果と直近診断を含め、省略をmanifestに明記します。全記録はローカルに残り、「詳細ZIP」でまとめられます。
- 提出支援：停止・例外時にZIPを生成し、ファイル自体をクリップボードへコピーできます。提出先への自動送信は行いません。

## 検証状況

0.5.0はLinuxで96件中91件成功、Windows専用5件はスキップ。セッション制御、診断の学習分離、失敗時の判定、WALを含むDBバックアップ、破損DBがあってもログを提出できること、記録の保存上限、ソースだけのEXEを確認しています。前版0.4.0ではWindowsで86件全件成功（スキップ0件）。現行版でもWindowsの単体・配布テスト段階が成功し、本ツールを閉じて再起動する位置復元の検査を含みます。これらはゲーム連携の実証ではありません。ダウンロード障害9項目、実アプリUI、ランタイム・モデルの初回/再導入、追加OCR両方式の実導入と認識、ZIPのファイルコピーも確認済みです。架空ゲームの実行コードと連携試験は削除しました。

対象ゲーム本体・ライセンス・実行環境がないため、実ゲーム固有の描画取得、背面入力の受理、実際の日本語画面での認識、任意シーンからの攻略成功は未確認です。これらは実ゲームとの連携検証が必要です。

## 開発者向け

```sh
python -m unittest discover -s tests -v
python -m pip install ziglang==0.13.0
python tools/build_exe.py --zig <zig実行ファイルのパス>
python tools/package.py
```

`tools/build_exe.py` は自前ソースのZIPとPowerShell UIを埋め込んだWin32ランチャーを生成します。成果物は `dist/LocalGamePilot.exe` と SHA-256。`release/` は利用者が直接ダウンロードできるexeの配置先です。対応する検証範囲は VALIDATION.md に記録します。バージョンタグのpush時はWindows CI成功後にGitHub Releaseにも成果物を登録します。

ソースから起動する開発者は Python 3.12以上と `requirements.txt` を導入し、`python -m autoplayer` で実行できます。利用者向けにはこの作業は不要です。

同じキー列の入力後に画面変化が3回未確認になった場合、そのキー列の再送を保留して無入力観測へ戻し、LLMへ別の安全な操作・仮説の再検討を求めます。無反応だけでBackend異常とは判断しません。説明の英語応答を検出した場合は操作内容を保持したまま日本語に変換し、変換失敗時はキーを送らず再観測します。

回復時は過去のモデル説明をいったん外して現在の画像・OCRを読み直し、Ollamaへ渡す出力Schemaから保留中の単独キーを除きます。具体的な観察の代わりに説明用の例文を返した場合は、入力や攻略学習に使用しません。別の安全な行動を実モデルが選べるかは実ゲームでの確認が必要です。

OCRの数字間スペース（例: HP 1 5 / 1 5）を扱い、満HPなら回復条件がすでに満たされていることをLLMへ伝え、小目標の見直しを求めます。現在のHPの読取りに明確に反する達成報告は攻略の事実に採用しません。小さな自然変化で再送保留を解除せず、一定の判断回数後に再評価します。

画面判断は二段階です。まず目標・攻略知識・過去の説明を渡さず、現在画像とOCRから場面・位置・通路・障害物・危険を観察させます。その後、同じ画像と観察結果を使って小目標と行動を計画させます。両方をUI・ログで区別できます。同じモデルによる未検証の観察なので正しさの保証はなく、モデル要求が増える分だけ処理時間も増えます。
